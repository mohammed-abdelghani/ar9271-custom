# 🛠️ تحسينات الاستقرار والسرعة على جانب الجهاز المضيف (Host-side Tuning)

> **التاريخ:** 2026-11-14 | **الكيرنال:** 6.12.117+deb13-amd64 | **الإنترفيس:** `wlx001122334455` (0cf3:1006)
> **الهدف:** استقرار الشريحة في التشغيل والاتصال + استقرار وسرعة الإنترنت — دون تعديل درايفر/فيرموير.

---

## 1️⃣ ما طبّق مباشرة (بدون sudo — على مستوى NetworkManager)

| التغيير | الأمر |
|---|---|
| تعطيل توفير الطاقة على ملف اتصال الشريحة | `nmcli connection modify ".... 1" 802-11-wireless.powersave 2` |
| تفعيل التعديل على الاتصال الحي | `nmcli connection up ".... 1"` (إعادة اتصال سريعة) |

**النتيجة المقاسة (ping إلى الجيت واي `192.0.2.158` عبر الشريحة):**

| القياس | قبل (PS مفعّل) | بعد (PS معطل) |
|---|---|---|
| متوسط RTT | 10.6 ms | **3.7 ms** |
| أقصى RTT | 105.7 ms | **11.9 ms** |
| الانحراف (mdev) | 25.4 ms | **1.8 ms** |
| فقدان حزم | 0% | 0% |

نزلات الـ 105ms هي التوقيع الكلاسيكي لتوفير الطاقة (الشريحة تستيقظ مع كل beacon).

## 2️⃣ ما يحتاج تشغيل مرة واحدة بـ sudo — `apply-stability-tuning.sh`

```bash
sudo bash apply-stability-tuning.sh
```

ينشئ 4 ملفات (كل واحد مستقل وقابل للحذف للتراجع):

| الملف | الغرض |
|---|---|
| `/etc/NetworkManager/conf.d/90-wifi-powersave-off.conf` | تعطيل PS لكل اتصالات الواي فاي (حتى الشبكات الجديدة) |
| `/etc/modprobe.d/ath9k_htc-stability.conf` | خيارات دائمة: `use_dev_fw=1 ps_enable=0 btcoex_enable=0 nohwcrypt=1` |
| `/etc/udev/rules.d/91-ath9k-htc-stability.rules` | منع USB autosuspend للشريحة (0cf3:1006) — يمنع فقدان الاتصال بعد الخمول |
| `/etc/sysctl.d/91-wifi-internet-tuning.conf` | TCP: BBR + qdisc `fq` + بافرات 16MB + `slow_start_after_idle=0` + `mtu_probing=1` |

**لماذا هذه الخيارات؟**

- **`use_dev_fw=1` دائم:** سابقاً كان يضبطه `deploy.sh` مؤقتاً فقط (`modprobe ath9k_htc use_dev_fw=1`) — عند إعادة التشغيل يرجع 0 والفيرموير المطوّر لا يُحمّل. الآن الدائم.
- **`nohwcrypt=1`:** التشفير العتادي في AR9271 مصدر مشاكل فك مفتاح/انقطاع معروفة؛ نقل التشفير لمعالج الجهاز (اللابتوب) يزيد الاستقرار بأثر ضئيل على الـ CPU. للترجاع: احذف السطر أو غيّره لـ 0.
- **USB autosuspend:** كان معطلاً يدوياً في الجلسة فقط (`power/control=on`) وبدون قاعدة udev — كان سيفقد عند أول إعادة تشغيل/إعادة تركيب.
- **BBR:** متاح في الكيرنل (`/lib/modules/.../tcp_bbr.ko.xz`) لكن غير محمّل — السكربت يحمل الموديول ويجعله الافتراضي. BBR أفضل من cubic على وصلات Wi-Fi ذات فقدان حزم.
- **البافرات 16MB:** الافتراضي (`rmem_max=212992` = 208KB) يكبح TCP عند أي RTT متوسط مع نافذة كبيرة.

⚠️ **خيارات الموديول (2) تطبّق فقط بعد إعادة تحميل `ath9k_htc`:** إما إعادة تشغيل الجهاز، أو `sudo ~/ath9k-fw-build/deploy.sh`.

## 3️⃣ اكتشافات مهمة عن "سرعة الإنترنت"

1. **عنق الزجاجة = خط الإنترنت نفسه، وليس الشريحة:**
   - تحميل 30MB عبر الشريحة: **498 KB/s (~4 Mbps)**
   - تحميل 25MB عبر واي فاي اللابتوب المدمج `wlp2s0`: **326 KB/s (~2.6 Mbps)** — أبطأ!
   - إذن الشريحة تعمل بكفاءة كاملة ضمن حدود الاشتراك. البافرات/BBR تحسّن الثبات لكنها لن تكسر سقف المزوّد.
2. **ICMP للخارج محجوب من المزوّد/الراوتر:** `ping 1.1.1.1` و `8.8.8.8` يفشلان 100% عبر **البطاقتين معاً**، بينما TCP يعمل. اختبارات الإنترنت مستقبلاً: `ping` إلى الجيت واي `192.0.2.158` أو قياسات TCP (`curl -w '%{time_connect} %{time_starttransfer}'`).
3. **القناة 10 مشتركة:** SSID `....` (الخاصة) و `NEIGHBOR-AP` (إشارة 100% — اسم مُعمّى) على نفس القناة 2457MHz. لو NEIGHBOR-AP راوتر جار → ازدحام هوائي يقلل السرعة المحلية؛ لو راوتر ثانٍ عندك → لا مشكلة. تغيير قناة الراوتر لـ 1 أو 13 يفصل التداخل.
4. **الإنترنت الحالي يمر عبر `wlp2s0`** (metric 600) والشريحة احتياطية (metric 601). لو المطلوب جعل الشريحة هي مصدر الإنترنت الأساسي — تعديل `ipv4.route-metric` — قل ذلك وسنضبطها.

## 4️⃣ التراجع (Revert)

```bash
sudo rm /etc/NetworkManager/conf.d/90-wifi-powersave-off.conf \
        /etc/modprobe.d/ath9k_htc-stability.conf \
        /etc/udev/rules.d/91-ath9k-htc-stability.rules \
        /etc/sysctl.d/91-wifi-internet-tuning.conf
nmcli connection modify ".... 1" 802-11-wireless.powersave 0
sudo sysctl --system && nmcli general reload
```
