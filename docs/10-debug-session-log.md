## 1️⃣ الخط الزمني للأعطال (كلها اتشخصت واتحلت)

| # | العطل | السبب الجذري | الإصلاح |
|---|---|---|---|
| 1 | **تجمد النظام عند `macfilter add`** (الكارت متصل) | استنفاد **reply pool** (buffers = 2 فقط) لحظة ضغط الترافيك → `adf_os_assert(0)` في `wmi_cmd_rsp` → **الشريحة تتعلق نهائياً** | إصلاح رقيّق: فشل التخصيص = طبع + drop (الشريحة حية، الـ host يعيد) |
| 2 | **الأوامر الكبيرة timeout متقطع** (يشتغل مرة ويفشل مرة) | **حد الرد الفعلي ≈ 64B payload (68B كلي)**: رد 64B دخل حرفياً، رد 72B فشل → `put_tail` يرجع NULL → memcpy على NULL | **تصغير كل الردود** (rate_usage 64→32B، rssi 72→52B بـ 48 bin) + guard الحجم في `wmi_cmd_rsp` |

| 4 | **الأوامر تموت بعد دقائق من الاتصال** (telemetry seq=1400 تتجمد) | **تلي ماتري دورية كل 2s استنزفت credits الـ CTL endpoint** (1400 event) → الطابور اتقفل → الردود ماتت معاه | **سحب الإرسال الدوري نهائياً** — العدادات محفوظة، والرجاع لاحقاً بتصميم pull-based |

## 2️⃣ القواعد الذهبية المكتشفة (ملزمة لأي تطوير قادم)

1. **سقف حزمة WMI control على السلك = < 64B تماماً** — أي حزمة (HTC 8B + WMI hdr 4B + payload + credit trailer ≤4B) تلمس 64B-تماماً **تعلق USB controller بعد إرسالها** (EP3 IN يبث EOVERFLOW، EP4 OUT يتوقف عن ACK) — اتحسم بـ usbmon، انظر docs/13. الرد الآمن ≤ 60B كلي (أي payload ≤ ~44-48B). القاعدة القديمة ("64B payload يفشل فوقها") كانت غير دقيقة
2. **فشل تخصيص الردود يجب أن يكون رقيقاً** — أي `adf_os_assert(0)` في مسار الردود = تعليق الشريحة
3. **ميزانية `.text` = `iram_seg` 39,680B** — بعد دفعة الإصلاح (docs/13): **35,467B مستخدمة + هامش ≈3,709B**. أي ميزة جديدة تُقاس ضد الهامش قبل البناء
4. **credits الـ CTL endpoint محدودة** — لا إرسال أحداث دورية من داخل الـ rx tasklet أثناء الاتصال
5. **الشريحة المعلقة بـ assert** → الاسترجاع الوحيد = **فك فيزيائي** (الـ authorized toggle لا يعيد تشغيل CPU معلق) — الـ wedge نفسه (64B packet) يعيد إقلاع الشريحة ذاتياً عبر USB re-enumeration عند أول محاولة استيقاظ، وقد يعلق نهائياً حسب حالة الـ CPU وقتها
6. **ميزانية الـ WMI buffer pool (100B) لا ترفع** — المحاولة (200B) استنزفت heap الإقلاع وقتلت طبقة WMI بالكامل
7. **(جديد docs/13) `CONFIG_ATH_DEBUG` غير مفعّل** → رسائل `ath_dbg` (بما فيها timeout prints) لا تظهر في dmesg أبداً — الاعتماد على `wmi_diag`
8. **(جديد docs/13) mac80211 PS يعيد ظل ريجسترات MAC في ROM عند كل wake** — أي knob ريجيستر يحتاج `power_save off` (أو ترافيك) ليحتفظ بقيمته
